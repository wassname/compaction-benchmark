## Chronological evidence

### Implementation

`extensions/council-compaction.ts` is the primary source for what ran. It contains:

> `const drafts = await Promise.all(`
> `  ADVISORS.map(async (advisor) => {`
> `    ... const result = await compact(event.preparation, ...);`
> `    return { advisor, result };`
> `  }),`
> `);`

It then builds the synthesizer input only from the advisor outputs:

> `const draftsText = drafts.map(({ advisor, result }) => \`## ${advisor.model}\\n${result.summary}\`).join("\\n\\n");`
> `... text: \`<drafts>\\n${draftsText}\\n</drafts>\\n\\nMerge the drafts. Keep supported agreement and useful non-conflicting detail. Omit contradictions and guesses.\``

Observation: the final Luna call does not receive `event.preparation` messages. Inference: this is a summary-only merge; it cannot source-check a disputed detail against the original prefix.

## Hypotheses

### H1 [method | Highly Likely | 80%]

- **Mechanism:** A summary-only merger loses details that occur in only one draft, and cannot verify conflicts against the source. The `omit contradictions` instruction also tends toward deletion rather than retaining a qualified detail.
- **Evidence:** The final prompt is exactly: > `Merge the drafts. Keep supported agreement and useful non-conflicting detail. Omit contradictions and guesses.` The measured result is `3.9±2.4` pre facts versus Pi default `6.2±1.9`.
- **Contrary evidence:** The final summary could union unique non-conflicting details; advisor summaries themselves were not saved, so actual loss location is unmeasured.
- **Discriminating test:** Save all three drafts and annotate each gold fact as present in zero/one/two/three drafts and in the merge. If one-draft facts are lost disproportionately, this mechanism predicts it.
- **Fix/action:** Do not treat a summary-only merge as a likely improvement. If continued, require advisor fact manifests with source offsets, then have the merger retain supported unique facts rather than only agreement.
- **Interpretability:** partial; the negative result applies to this merge prompt and output budget.

### H2 [bug | Almost Certain | 95%]

- **Mechanism:** The advertised high-reasoning advisor setting was not applied by the extension.
- **Evidence:** The source declares `thinking: "high"` but passes no `advisor.thinking` or equivalent reasoning parameter to `compact()`; the only explicit reasoning option is the Luna call’s `reasoning: "high"`.
- **Contrary evidence:** The model registry might carry a high default for these models, but no artifact records it and the extension's field cannot control it.
- **Discriminating test:** Log the resolved model object and provider request reasoning parameter for one cell. A request explicitly marked high would reduce this concern; absence confirms it.
- **Fix/action:** Either set advisor thinking through the API/model mechanism that Pi supports and record it, or remove `high` from the method description.
- **Interpretability:** no for any claim about *high-reasoning advisors*; yes for the actual unspecified advisor defaults.

### H3 [measurement | Likely | 65%]

- **Mechanism:** The merged summaries are shorter, leaving less retained context than Pi default, and the benchmark does not report summary length separately from raw retained tail.
- **Evidence:** Council `context after` is `19.4±2.4k`; Pi default is `21.3±2.3k`. The real-merge smoke has `estimatedTokensAfter: 16344`.
- **Contrary evidence:** Context-after overlaps substantially and is total retained context, so it cannot localize whether the difference is raw tail or summary output.
- **Discriminating test:** Persist summary token count and raw-tail token count for every cell; match total summary budgets in a rerun.
- **Fix/action:** Add those two fields before comparing merger quality.
- **Interpretability:** partial; observed recall difference is real for configured runs, but not attributable specifically to merging quality.

### H4 [harness | Likely | 70%]

- **Mechanism:** `run-missing` is too broad for a targeted rerun. It retried all historic gaps, producing twelve unrelated failures in a job labelled as a council test.
- **Evidence:** The log's failed list includes Smart Compact command failures and absent judge seats for CC Compact, Handoff, and Kimi Lab Report. None names `council-default`.
- **Contrary evidence:** All council cells completed and graded, so this did not corrupt the council row.
- **Discriminating test:** Add `run-method --all-trials council-default` or a fixture/trial filter, then verify the log has only intended cells.
- **Fix/action:** Use a scoped runner for reruns.
- **Interpretability:** yes for the council row; no for treating job success as an all-method health check.

## Decision

1. **Resolve-condition verdict: met.** The job asked to “compare 9-run prefix recall”; nine council grade files exist and the generated table reports `3.9±2.4` pre facts.
2. **Prediction check:** no prediction was recorded before the job. The observed result contradicts an implicit hope that summary merging would improve recall.
3. **Earliest unsupported link:** “multiple independent drafts preserve more usable facts” is unsupported because advisor draft content was not persisted or measured.
4. **Validity:** `P(result is invalid) ≈ 0.15–0.25` for the claim “this exact summary-only merge underperformed Pi default”; it is a credible negative for the implementation. `P(result is invalid) ≈ 0.85–0.95` for the claim “high-reasoning advisors were tested,” because the setting was not wired.
5. **Three highest-information clues:** (a) `3.9±2.4` vs `6.2±1.9` on complete 9/9 rows; (b) source-only merge input proves the changed mechanism; (c) unused advisor thinking field breaks the intended compute comparison.
6. **Missing metrics:** highest value: saved advisor drafts plus per-fact draft/merge coverage; then advisor provider reasoning settings; then summary-versus-tail token counts.
7. **Bugs requiring code changes:** wire/log advisor thinking; use a scoped rerun command; persist drafts and token components.
8. **Misconceptions requiring reinterpretation:** do not say “smarter models are worse” or “high-reasoning advisors failed.” The supported statement is narrower: this unverified draft-only merge did not improve recall.
9. **What would change the verdict:** a rerun with recorded high reasoning and fact-manifest merging that scores above Pi default would reverse the negative conclusion about merging; it would not change the result for this implementation.
10. **Recommended sequence:** first fix and smoke-test advisor reasoning logging. Then either stop this avenue (lowest cost, justified by the negative) or run one attributable improvement: saved fact manifests with source offsets, fixed total output budget, and 9/9 grading. Do not combine a new merge format, new advisors, and a changed tail budget.
