
# Compaction recall benchmark

## User voice

> Find three complex sessions and rewind each to its first compaction.
>
> For each session, load it in Pi and ask for 20 durable facts for a compaction-recall benchmark. Save these questions and their gold answers.
>
> Rewind each session and run the comprehension test without compaction as a baseline. The score should be above 90%.
>
> For each compaction method, load the untouched session in isolated Pi RPC mode with no unrelated extensions, compact it, ask the same questions, and score the answers.
>
> Produce a clear Markdown results table for every extension. Start with Pi's built-in baseline, `pi-blackhole`, `pi-smart-compact`, `pi-context`, `@pinet/model-aware-compaction`, and `context-fold`; verify the exact package names before running them.
>
> Test whether compaction quality changes with a smart or dumb model and high or low reasoning by using `pi-custom-compaction`.
>
> Also test the Claude compaction prompt from `pi-cc-compact`.

## Appendix: facts gathered before planning

- Local Pi is `@earendil-works/pi-coding-agent` 0.84.4. Its RPC API has first-class `compact`, `set_auto_compaction`, `set_model`, `get_state`, `get_session_stats`, `get_entries`, and `get_last_assistant_text` commands. `agent_settled` is the terminal event after retries and queued work.
- Pi documents `--no-extensions -e npm:<package>` as the way to ignore discovered extensions while loading one temporary package. `PI_CODING_AGENT_DIR` changes the config/package root; it therefore needs a fresh directory per method.
- The registry names and versions observed during planning were `pi-blackhole@0.4.10`, `pi-smart-compact@9.5.0`, `pi-context@2.1.2`, `@pinet/model-aware-compaction@0.2.13`, `context-fold@0.3.2`, and `pi-cc-compact@0.1.0`. Pin the versions recorded at run start rather than relying on `latest` later.
- `pi-blackhole`, `pi-smart-compact`, `context-fold`, and `pi-cc-compact` intercept Pi's compaction path. `pi-context` exposes an agent tool that creates a summarized continuation branch. `@pinet/model-aware-compaction` changes when Pi calls its existing compactor and is disabled until configured; a forced RPC `compact` would only benchmark Pi default under its name.
- The primary result measures compacted context, not retrieval from raw history. Disable all recall and filesystem tools during questions; report methods whose main feature is retrieval or trigger policy in a separate eligibility table.
- Use `openrouter/deepseek/deepseek-v4-flash` for the first baseline pass because its 1M-token context fits all fixtures. Escalate only if an uncompacted fixture scores below 19/20 after invalid gold items are repaired.
- `pi-blackhole` normally builds observational memory while a session runs. Loading an old fixture and compacting immediately is a cold-load test of its current behavior, not a test of a session that had Blackhole installed from the start.
- [`pinion05/pi-cc-compact`](https://github.com/pinion05/pi-cc-compact) used the same corpus/model, 10 interleaved trials, raw outputs, latency, and entity recall. Its own caveat says this was surface-keyword recall on one self-referential corpus, not resumed task continuity. This plan keeps its reproducibility practices but uses real compacted-and-resumed Pi sessions and semantic, source-evidenced questions.
- [`nicobailon/pi-custom-compaction`](https://github.com/nicobailon/pi-custom-compaction) 0.2.5 intercepts both native and extension-triggered compaction. Its policy independently selects the summary model, thinking level, template, and retained token budget. It warns that an undersized model can silently fall back, so each ablation must prove the actual summary provider/model.
- The Claude prompt will come from `pinion05/pi-cc-compact`, as the user specified. Its source preserves the full nine-section prompt and the no-tools instructions; the benchmark will store the exact source URL, commit, and content hash.

## Learnings

- Gold-generation models paraphrase evidence, so `evidence_quote` must be repaired to one exact contiguous source span and then matched to exactly one entry ID.
- `pi-custom-compaction` 0.2.5 does not write its selected summary model into compaction details; ablation runs need separate positive model evidence, not only absence of its fallback warning.
- A `pi-custom-compaction` template is wrapped by that extension's own system and summary instructions. It can test a Claude-derived nine-section format, but only `pi-cc-compact` tests its claimed exact Claude prompt and wrapper.
- Exact substring matching is insufficient: the first generated gold used arbitrary short windows that did not support the answer. Evidence must be exact and self-contained; multi-clause answers may need multiple quotes.
- A grader given only the 20 gold answers cannot tell an invention from a true detail elsewhere in the fixture. Blind graders must load the untouched source while keeping the method identity hidden.
- A pre-boundary fact repeated or paraphrased in the retained tail does not test compaction recall; each pre-boundary item needs a tail-leakage review.
- DeepSeek can pair a plausible fact with the ID of a nearby `/supervise` entry that does not contain it. Keep model output as raw evidence and validate a separate human-curated answer file.
- Supervisor snapshots repeat earlier messages inside later source entries. Evidence may repeat before the boundary, but a pre-boundary quote repeated in the retained tail is invalid.
- DeepSeek V4 Flash was not stable enough for the baseline: one `lucid3-first` rerun fell to 16/20 and one grader emitted a pseudo tool call instead of JSON. The predeclared escalation rule therefore selects Terra/high for all scored answer and grading runs.
- `../wassname-ml-bench/bench.py` already supplies the relevant judge design: provider-independent seats, gold/off-topic anchors, exact answer-line citations, strict-schema correction, friction notes, and measured judge-choice variance. Reuse those controls instead of adding an ad hoc second judge.
- A source session cannot be resumed as the judge because historical supervisor instructions remain active; use a fresh evaluator session with source text quoted as inert evidence, cap output tokens, and require a calibrated panel identity.
- Reruns must delete old run directories before starting, and validation must bind each answer to the current method-manifest hash; otherwise stale correction attempts or pre-change method artifacts can be mistaken for current evidence.
- One prompt should not grade gold alignment and source-grounded invention together: the long source evidence swamps empty or unrelated candidates. Use a short gold-versus-candidate pass and a separate source-versus-candidate invention pass.
- Calibration must gate on a discrimination gap, not exact label reproduction: exact per-variant counts failed all five seats. ml-bench seats a judge when its gold-minus-off-topic gap clears 0.5.
- The off-topic anchor must be a *different fixture's* answers, not a within-fixture shift: all `lucid-aug20` facts are about oracle KL, so a shifted answer is still a real session fact and content-matching judges retained it (deepseek 19/20, glm/gemma/inkling 20/20). Cross-fixture answers are genuinely unrelated.
- A judge that content-matches rather than aligns by item number will retain an off-topic answer that happens to be a real fact; number-locked grading is required.
- The unscored `judge_note` must tolerate `null`: qwen returned `"judge_note": null` on every attempt, so a strict `isinstance(str)` check killed the seat even though its facts were correct.
